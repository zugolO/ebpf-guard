# Список rule_id с action in [kill, block, throttle] (правил репозитория),
# у которых нет условия на значение аргумента/поля события — только на
# идентичность вызывающего процесса (comm) или вовсе без условий (волна
# 5.9.4b, находка №53).
#
# Зачем этот файл. Разрушительное действие (kill/block/throttle), решение о
# котором принимается только по имени процесса, не различает "чужую"
# деструктивную команду от штатной работы легитимного инструмента с тем же
# именем (systemd, containerd, dockerd, runc и т.п. управляют cgroup-BPF
# штатно). Машинный инвентарь — RuleEngine.DestructiveRulesWithoutArgCondition
# (internal/correlator/rules.go) и TestDestructiveRulesInventory_RepoRules
# (internal/correlator/rules_coverage_test.go) — перечисляет каждое такое
# правило репозитория и требует, чтобы оно либо получило настоящее условие на
# аргумент, либо было записано сюда с обоснованием и датой.
#
# На №2.9.3/начало 5.9.4b все 6 правил репозитория с action kill/block
# (throttle пока не используется ни в одном правиле) уже несут условие на
# значение поля события (arg0/new_cgroup_id/filename/name), поэтому сейчас
# этот список пуст. ebpf_subversion_unauthorized_caller — правило, из-за
# которого пункт вообще появился (comm not_in вместе с условием на arg0) —
# не попадает сюда механически (arg0 — настоящее условие на аргумент), но её
# false positive на системных демонах решён отдельно: понижением action до
# alert, см. rules/ebpf-subversion.yaml и plan.md, раздел 5.9.4b (долг —
# "чужая программа" неразличима без парсинга bpf_attr/владения объектом,
# которого коллектор syscall сейчас не даёт).
#
# Формат: один rule_id на строку, пустые строки и строки с # игнорируются.
