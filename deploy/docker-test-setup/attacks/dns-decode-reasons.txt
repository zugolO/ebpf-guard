# Реестр причин ebpf_guard_dns_decode_errors_total{reason=...}, волна 5.9.6g,
# долг №65 (постановка 5.9.5c: три гипотезы — ответы с sport 53, TCP-DNS/
# mDNS, обрезка по DNS_MAX_PAYLOAD — не разделены).
#
# Отличие от silent-rules.txt/intentional-loss.txt: те — про
# ebpf_guard_alerts_total (правила детекта). Этот файл — про декодер DNS:
# любой reason с ненулевым счётчиком в final-metrics обязан быть здесь,
# иначе run-gate.sh (секция "DNS decode errors: причины разделены")
# проваливает его как непонятную потерю разбора. Порог по-прежнему не
# ставится (урок 5.9.1f) — реестр обязывает объяснить, не занизить.
#
# ФОРМАТ: одна строка — "<reason> <категория> <пояснение без пробелов вокруг
# — используйте _ вместо пробела или пишите пояснение блоком выше>".
# Категории:
#   fixed   — причина установлена и исправлена (декодер больше не должен
#             давать эту причину на новых событиях того же вида).
#   known   — причина установлена, не является дефектом (например,
#             not_a_query на легитимных QDCOUNT=0 пакетах).
#   pending — причина НЕ установлена, но количество и контекст записаны:
#             диагностика по 5.9.6g (direction/payload_len в hex-логе,
#             internal/collector/dns.go) добавлена, чтобы СЛЕДУЮЩЕЕ
#             срабатывание можно было отнести к одной из трёх гипотез
#             (sport-53 ответ / TCP-DNS-mDNS / DNS_MAX_PAYLOAD-обрезка);
#             сама причина конкретных прошлых событий восстановлению не
#             подлежит — sample_hex того прогона уже потерян (тот же класс
#             ограничения, что 5.9.6e зафиксировала для grafana/08:46:32).
#
# ─────────────────────────────────────────────────────────────────────────────
# №2.9.5 (final-metrics-20260821_091936.txt): bad_qname=25, too_short=1,
# остальные четыре reason'а (not_a_query, truncated_payload,
# compression_loop, unparseable) на этом прогоне — 0 (материализованы
# нулём с первого скрейпа с 5.9.5c, RegisterMetrics в dns.go — это не
# отсутствие метрики, а подтверждённый ноль).
#
# too_short=1: до этой правки диагностика логировала весь record.RawSample,
# но фиксированный заголовок dns_event сам занимает 63 байта, а
# malformedLogger обрезает лог до 48 — те же 48 байт для too_short физически
# не могут содержать что-либо, кроме первых полей заголовка. Записи короче
# 63 байт целиком не разбираются никакой правкой этой волны: одна запись за
# аптайм, недостаточно для гипотезы, и extra-поля (direction/payload_len) для
# too_short не логируются намеренно (dns.go: сами эти поля читаются из того
# же заголовка, которого не хватает).
too_short pending известно_1_за_аптайм_№2.9.5,_запись_короче_63_байт_фиксированного_заголовка,_диагностика_direction/payload_len_недоступна_по_построению_для_этой_причины
#
# bad_qname=25: 5.9.6e установила, что единственный захваченный sample_hex
# (grafana/08:46:32) был полностью заголовком без байта payload — старая
# диагностика резала лог на 48 байт ДО учёта 63-байтного заголовка, поэтому
# ни для одного bad_qname прошлого прогона гипотеза не восстановима. 5.9.6g
# чинит это на будущее (dns.go теперь режет sample по dnsRawEventFixedLen,
# logger.record получает direction+payload_len отдельными полями), но 25
# случаев №2.9.5 сами уже недоступны для разбора — таких данных просто нет.
