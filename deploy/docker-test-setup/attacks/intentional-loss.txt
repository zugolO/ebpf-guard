# Волна 5.9.2b (находка №39): syscall-правила, чей `nr` не пересекается с
# in-kernel allowlist после этой волны. Формат остаётся «один rule_id на
# строку без хвостовых комментариев» — run-gate.sh:628-629 сравнивает строки
# через `comm -12`, и любой текст после rule_id сломает совпадение. Причина
# для каждого — здесь, в этом комментарии, а не на строке правила:
#
#   cis_5_2_1_privileged_container   — nr=160 (setns family variant), не открыт:
#       нет отдельного attack-шага, отличного от уже открытого 308 (setns).
#   mitre_sandbox_detect_cpuid       — nr=135 (personality), нет attack-шага.
#   mitre_arp_spoof_raw_socket       — nr=41 (socket(AF_PACKET)), нет attack-шага.
#   rootkit_anonymous_exec_memory    — nr=9 (mmap) — слишком общий syscall,
#       открывать целиком означало бы отменить волну 0.5 (5800→226 соб./с);
#       нужен BPF-side фильтр по PROT_EXEC-флагу, не входит в 5.9.2b.
#   rootkit_userfaultfd_create       — nr=323, нет attack-шага.
#   rootkit_kexec_load               — nr=246/320, нет attack-шага (требует root
#       и реальной загрузки образа ядра — небезопасно для стенда).
#   sigma_mprotect_exec_heap         — nr=10 (mprotect) — тот же случай, что
#       rootkit_anonymous_exec_memory: слишком общий syscall для allowlist.
#   sigma_prctl_dumpable              — nr=157 (prctl), нет attack-шага.
#   sigma_seccomp_filter_install     — nr=317 (seccomp), нет attack-шага.
#   sigma_world_writable_dir_created — nr=83/258 (mkdir/mkdirat), нет attack-шага.
#   web_blind_sqli_heuristic         — nr=35/162/206 (nanosleep-family), нет
#       attack-шага, отличного от общего sqli-сценария.
#
#   ransomware_mass_rename (nr=82) и ransomware_backup_delete (nr=87/263) —
#       ИСПРАВЛЕНО 2026-08-19 по факту живого старта агента на стенде. Волна
#       5.9.2b записала их как достижимые, потому что 82/87/263 есть в
#       config/config.yaml. Стенд этот файл не читает: он работает на
#       deploy/docker-test-setup/config-test.yaml, где kernel_filter вообще не
#       задаёт monitored_syscalls, поэтому эффективный allowlist — это
#       DefaultMonitoredSyscalls() (22 номера, без 82/87/263). Агент при старте
#       печатает 13 немых правил, а не 11. Открывать три номера не стали:
#       rename/unlink/unlinkat — высокочастотная тройка на активной машине, а
#       attack-шага под ransomware на стенде нет вовсе (ни в
#       detection-baseline.txt, ни в run-all-attacks.sh), то есть открытый вход
#       был бы чистым приростом idle-шума без единого срабатывания — ровно то,
#       что запрещает запрет №1 волны 5.9.2. Разблокируется волной 6 вместе с
